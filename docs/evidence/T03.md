## 行为实现要点

- **流式回合**：`respond()` 只经注入的 `ModelClient` 调用模型（不 import Harness、不联网）。事件顺序：`phase`（分析/生成）→ `delta`（正文，尾部元数据被缓冲不展示）→ `evidence`（累计）→ `activity`（可选）→ `position` → `done`；失败/取消终止为 `error`。模型流中途失败时，已生成文本放进 `error.details.partialText`（≤2000 字）供 Host 保留“已完成内容 + 继续路径”。
- **结构化输出**：要求正文后输出 `<<<TEACHING_META>>>` + JSON；解析失败最多做一次修复调用，仍失败则纯文本降级（不崩、不创建活动、原因写入 uncertainty/limitations）。模型未按约定分隔符时不会把元数据当正文展示（已展示部分除外，会标注）。
- **来源纪律**：模型只能通过 M/C/W 编号声明使用哪些 Host 提供的资料；引擎用真实 `SourceAnchor` 回填 `EvidenceReference`，不存在的编号被忽略并告警（**不伪造 anchor/页码/原文**）。支持区分 `course-source`/`other-course`/`external-web`/`model-knowledge`/`derivation`；未引用课程资料时自动追加 `model-knowledge` 并进入 limitations。`experiment` 证据不在本回合产生（契约输入无运行结果，需 Host 在活动运行后追加，见局限）。
- **冲突与不确定**：模型可报告 `conflicts`（`convention`/`substantive`/`unresolved` + 依据编号）；约定差异与实质错误分开呈现并附依据；`materialWarnings` 全部进入 uncertainty（`资料不确定：…`）；资料不足/外部检索空/模型无图像能力进入 limitations。
- **教学策略**：按任务形态（概念/证明/程序/阅读/辨析/开放式论证/习题）给不同骨架；概念讲解为“直觉→准确表述→适用条件→类比边界”，证明按目标展开；阅读任务无资料时退化为模型知识直觉讲解并标注；学情等级（exposed/practiced/checked/mastered）影响形式（已掌握转复习）；学生 `requestedForm`/原话要求覆盖形式但保留目标；练习中的临时追问回答后位置回到原阶段并给“回到当前练习”按钮。
- **双语**：`zh`（保留原文术语）、`en`、`bilingual` 三种系统指令；术语保留偏好进入提示。
- **活动提案**：校验 `kind` 与 `payload.type` 一致、必填字段、quiz 正确选项是选项子集、rubric 非空、reading-task anchors 由系统回填；类型/阶段不匹配或非法 payload 不创建活动并写入 uncertainty；practice/transfer 阶段拒绝纯讲解卡；学生要求完整答案时 `independent=false`。
- **分类**：`classify()` 一次小调用；模型失败/坏 JSON 时用规则兜底（不抛异常），识别切换形式/要答案/练习/诊断/复习等。
- **诊断**：提示词要求指出学生具体误解（引用原话/步骤）并给针对性追问或诊断活动，而不是只给正确答案；诊断元数据可带 misconception/evidence/nextStep。

## 局限与下一步

1. **Host 接线**（Lead）：`chat.send` 需组装 `TeachingTurnInput`（Corpus search → `material`；联网能力 → `webResults`；跨课 → `crossCourse`；资料问题 → `materialWarnings`；session/course/revision/profile/learning/history）；消费事件：`phase→progress`、`delta→delta`、`activity→用 newId('act')/nowIso 补 id/时间/sessionId/courseId 后 saveActivity`、`evidence→消息 evidenceRefs`、`position→session.position`、`done→教师消息+meta`、`error→错误消息`。`ActivityProposal` 不含 id/时间/session/course，需 Host 补全。
2. **`experiment` 证据**：`TeachingTurnInput` 没有运行结果字段，本回合不产生 `experiment` 类证据；Host 应在活动运行/验证后把运行证据并入消息或下一轮输入（契约扩展需 Lead 决定，本任务未改契约）。
3. **真实模型质量**：提示词与解析已按“正文+尾部 JSON”设计，但真实模型遵循度、token 用量、时延未测；解析失败路径有单元测试，真实模型表现需 T08 采样。
4. **联网**：本模块不发起网络请求；AC16 的断网/外部不可达需 Host adapter 实测。
5. **分类兜底**：`classify()` 模型失败时用规则；规则只覆盖常见表达，Host 不应把分类当唯一路由依据。
6. **教学效果**：形式/骨架/冲突/诊断等只是策略与提示约束；是否真正“形成直觉并连接准确表述”需真实学生人工评审（AC19–AC22），本证据不宣称通过。
7. **`experiment-note` 活动**：payload 支持但本模块不创建运行证据；运行/验证由 T05/T06 提供。

## 整合期修复与真实 runtime 验证（Lead 追加，2026-11-04 晚）

Host 接入后，在真实 bundled runtime + dev profile + 宿主模型上验证，发现并修复两处解析鲁棒性问题（改动位于 `packages/teaching-core/src/teaching/parse.ts`，已跑该模块 65 项测试）：

1. **重复 META 标记**：模型有时在完整 JSON 之后再输出一个空的 `<<<TEACHING_META>>>`。原实现用 `lastIndexOf`，取到空尾部导致 JSON 解析失败并降级。现按“标记间分段、优先选可 JSON.parse 的段”选择元数据。
2. **activity 平铺**：模型可能输出 `{"type":"quiz","question":...}`（payload 字段直接平铺）而非 `{"payload":{...}}`。现在若无 `payload` 字段但存在已知 `type`，将 activity 自身视作 payload。

真实运行结果（`opencode-go/deepseek-v4.1-flash`，reasoning effort=max 的部署默认）：
- `chat.send` 流式事件 phase/delta/evidence/position/done 正常；正文含 `[M4]/[M6]` 资料引用与「模型补充」标注；
- 真实提案成功创建 quiz 活动（`act-22txaa2j643`，4 选项，correctOptionIds 正确落库）；
- 空正文/元数据损坏时按设计降级为纯文本并写 uncertainty/limitations（实测触发一次，学生可见“结构化元数据解析失败”说明）；
- 修复后 `sessions.get` 可恢复消息、教学元数据（intent/stage/nextActions/uncertainty）与活动。
