### 课程删除（学生数据控制，2026-11-04 晚）

用户反馈“已建课程不能删除”。实现：
- **Host**：`courses.delete` 增强：
  - 删除课程结构修订与课程记录；
  - 删除该课程全部会话，以及其活动记录、活动学生状态、对应 run 记录（不再遗留孤儿文件）；
  - 删除该课程学习记录（attempts/mastery/review/notes）；
  - 资料处理：默认仅解除课程关联（原资料解析记录保留）；勾选“同时删除资料解析记录”时删除仅属该课程的解析记录（`sources/<id>.json` 与单元/资产目录），**学生原始文件永不修改**；被其他课程共享的资料只解除关联。
- **客户端**：左侧栏每个课程行新增 🗑「删除课程」按钮 → 确认弹窗（说明将删除课程结构/会话/活动/学习记录；原始资料不改动；可选“同时删除资料解析记录”）→ 删除后刷新课程列表，若删除当前课程自动切到剩余课程或回到向导。
- **真实 dev runtime 实测**：
  - 课程含 1 会话 + 独立资料，`deleteSources=true` → details `{sessions:1, activities:0, sourcesDetached:1, sourcesDeleted:0}`（该资料被另一课程共享，正确选择“仅解除关联”）；课程随后 `not-found`；
  - 全新唯一资料课程，`deleteSources=true` → `{sourcesDeleted:1}`，磁盘上解析记录与目录均已删除、原文件未动；
  - 共享资料场景 `deleteSources` 默认 → `sourcesDetached=1`，另一课程资料关联不受影响。
- 自动测试：`pnpm test` 341/341、`tsc` 0 错误；桌面已重装最新构建（application=applied），用户刷新后可见 🗑 按钮。

### 图片/扫描件识别能力状态修正（2026-11-05，用户反馈）

用户看到「当前未启用图片/扫描资料识别能力」提示后询问。核查发现与修复：
- **Bug**：`bootstrap.features.imageOcr` 之前被**硬编码为 false**，即使本机 OCR 可用也显示未启用。现改为真实探测：`resolveOcrRuntime` 检查 tesseract、语言包（eng/chi_sim）与 pdftoppm，并带 `/opt/homebrew/bin`、`/usr/local/bin` 等常见路径回退（Desktop 从 Finder 启动时 PATH 很短）。
- **实测（dev runtime）**：`imageOcr=true`，语言 `eng+chi_sim`；bootstrap 提示改为「扫描件/图片将使用本机 tesseract OCR…低置信度内容会标注待核对」。
- **模型能力探测 bug**：此前用 `ctx.llm.resolveModel`（adapter 侧方法名）导致 imageInput=unknown；改为服务公开方法 `ctx.llm.resolveModelInfo`（并保持 `this` 绑定），现正确返回 `imageInput=yes`、contextWindow 读取兼容 `context.window` 结构。
- **能力边界（如实记录）**：本版使用“OCR 文本 + 原文定位”处理扫描件/图片；**不把页面图片直接发送给模型做视觉理解**。公式与复杂排版 OCR 可能不完整，低置信度会进入待核对问题清单；后续可加“按需把裁剪图片发送给图像能力模型”的视觉路径（需图像附件与隐私提示）。
