## 行为实现要点

- **独立性**（`classifyIndependence`，纯函数）：空作答且无选项 → `skipped`；`answerRevealed=true` 或 `helpLevel='full-answer'` → `answer-shown`（含模型代答，Host 约定见局限）；`helpLevel 1–3` 或 `hintsSeen` 非空 → `assisted`；否则 `independent`。`helpExposure` 如实记录提示层级/提示内容。
- **验证优先级**：Host 传入的客观 `validation`（quiz/run 的 `objective`/`quiz`）直接采用，**不会调用模型评分**；只有未提供或标为 `unverified` 时才走 rubric 路径。rubric 评分器抛异常/坏 JSON/调用失败 → `unverified` + `limits`，不假装通过、不抛异常穿透 Host。
- **rubric**：按 criterion `weight` 加权，缺项按不满足处理，加权 ≥ 0.6 才 `passed`；越界分数裁剪；`assessedBy='model-rubric'`，`confidence` 上限 `medium`，`limits` 固定说明“模型评分可能误判，可异议重检”。`rubricFromActivityPayload` 支持 `proof-task`/`open-question`。
- **掌握维度**（`explain/conditions/variants/transfer`，0/1 覆盖，只增不减）：仅“独立完成 + 验证通过 + 评价来源可信”的尝试贡献维度；quiz→conditions+variants、objective（运行）→variants、open（`assessedBy` 为 model-rubric/objective-runner）→explain+transfer、rubric→按评分项关键词映射（无关键词时保守按 explain+conditions）。`assessedBy='none'` 的开放题“通过”不计入。
- **等级**：`unseen`→`exposed`（只有接触/辅助/看答案/跳过）→`practiced`（有独立尝试但无有效通过证据）→`checked`（至少 1 条有效独立通过证据但维度未全覆盖或次数不足）→`mastered`（四维全覆盖 + ≥2 次有效独立通过证据 + 无未解决争议 + 无待复核）。单次证据不会 mastered；资料变化时暂封顶 `checked`。
- **依据可查**：`MasteryRecord` 保留 `evidenceAttemptIds`（该概念全部尝试）、`basis`（逐条尝试审计行 + 当前判定摘要，含独立/辅助/看答案/验证方式/贡献维度）、`uncovered`（未覆盖维度中文标签）。
- **争议/重检**：`dispute` 追加异议（原判定/依据/尝试不变）；`recheck` 把未决异议推进为 `recheck-due` 并生成按未覆盖维度的重检计划；重检结果作为新证据追加，不删除历史。
- **资料变化**：`markStaleForSources` 标记掌握记录 `needsRecheck`（等级暂封顶 `checked`）与相关尝试 `needsRecheck`，追加资料变化说明，历史保留；复习建议立即提示复核。
- **复习**：`computeReviewItems` 由注入时钟计算：未解决争议（after-dispute，立即）、资料待复核（立即）、后续课程需要且未掌握（upcoming-course-need，立即）、薄弱（low-mastery，1/2 天间隔）、掌握/检查后间隔复习（spaced，4/7/14/28/56 天，随独立通过次数增长，封顶 60）。`listReview` 返回未来 `reviewHorizonDays`（默认 7）内到期项。
- **错题**：`failedAttempts`/`isFailedAttempt` 过滤 `validation.passed === false` 的尝试；`listAttempts` 支持 session/course 过滤。
- **持久化**：全部经 `LearningRepository`（`get/save/listAll`）写入 `<dataDir>/learning/<courseId>.json`；错误转为 `Result`（`not-found`/`invalid-input`/`storage`），不把存储异常穿透 Host。

## 局限与下一步

1. **Host 接线**（Lead）：`attempts.submit` 需由 Host 补 `courseId/courseRevisionId`（来自 session）、`validation`（quiz 正确答案或 run 结果）、rubric 配置：
   `rubric: { resolve: input => rubricFromActivityPayload(activity?.payload), assess: createModelRubricAssessor(model, { language }) }`；
   `getRecord` 无记录时返回空记录（`courseRevisionId` 取 `resolveRevisionId(courseId)`，建议传 `CourseRepository` 的 active revision；未提供时为空串）；
   `upcomingConceptIds` 建议由 Host 按课程顺序/下一概念提供，否则没有 `upcoming-course-need` 复习项；`reviewHorizonDays` 可按 UI 需要设置。
2. **模型代答约定**：冻结契约的 `SubmitAttemptInput` 没有“答案来源”字段；本模块约定 Host 在模型代答/展示答案时提交 `answerRevealed=true` 或 `helpLevel='full-answer'`，据此分类为 `answer-shown`。若 Host 无法保证，需要契约扩展（Lead 决定）。
3. **掌握细则为通用初版**：维度映射（quiz→conditions/variants 等）与 mastered 阈值（四维 + 2 次独立通过）是可解释的保守规则，尚未经四类课程教学评审校准；T08 需按真实学生表现调整（TD12）。
4. **模型 rubric 不是权威**：`assessedBy` 如实标记，`confidence` 上限 medium，`limits` 固定展示；学生可异议重检。不得把模型评分当唯一依据。
5. **复习提醒范围**：本模块只给“当前应展示的复习建议”，不做插件外定时提醒（v1 不包含）；间隔策略是简单梯度，未做个体化遗忘曲线。
6. **真实桌面/重启/导出**：持久化格式与跨实例读取已用临时目录验证；真实桌面重启恢复、记录导出/删除/重置由 Host/T07 验证。
7. **并发**：`LearningRepository` 单文件读改写；同一课程并发提交尝试可能后写覆盖（LocalState 保证不出现半写文件）。Host 需串行化同一课程的学习写入（契约未提供 CAS）。
