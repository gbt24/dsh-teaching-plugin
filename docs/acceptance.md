# 验收矩阵

状态：验收设计，所有 case 初始为“未执行”。测试证据写入 `docs/evidence/Txx.md`；本表不是功能完成报告。

## 验证层级

1. Contract/integration：通过 module 的公开 interface 测试行为；选取真实格式 fixtures、资料修订、学生尝试、运行证据及恢复过程。
2. 真实桌面：在记录了版本的 Harness Desktop 中操作插件，验证加载、教学区域、当前模型、文件引用、实验与重启恢复。浏览器或 mock 成功单独记录。
3. 教学人工评审：以真实知识库和学生实际解释/作答检验四类课程。自动生成的“学生回答”只能用于测试数据流程。

## 四类端到端教学

样例主题是验收设计，可按真实资料替换同等难度主题。原资料、学生起点、活动、帮助程度、原回答、迁移题与评审依据都需要记录。真实资料由学生选择，公共仓库使用可分发 fixtures；来源核对不能只用模型自行生成的“教材”。

| AC | 样例 | 需要看到的证据 |
| --- | --- | --- |
| AC19 | AI：过拟合与泛化 | 引用课程定义；学生调整数据量/模型复杂度观察训练与验证差异；解释结果；面对不同数据情境独立提出并解释应对方案。 |
| AC20 | SICP：递归与过程 | 核对教材 Scheme 方言；真实运行与逐步解释；学生修改程序、预测并核对结果；独立分析未见程序，而非只记住样例输出。 |
| AC21 | 数学：导数、连续与适用条件 | 图形与极限/正式表述相连；检查不可导或条件不满足的反例；数值探索与证明结论分开；学生在新函数/情境中判断并说明依据。 |
| AC22 | 考研：阅读或概念辨析类任务 | 从真实课程中选择含干扰项/论证的题目；诊断学生误判依据；逐层提示；学生完成未见材料/变式并解释理由，检验非编程、非纯计算教学。 |

四类均需人工检查：目标适配、来源准确、直觉与正式知识连接、学生参与、错误诊断、独立迁移。发现学生未掌握时，产品正确行为包括如实记录并调整教学，而非为了“通过测试”标成掌握。

## 规模样本与测量

建议基准为约 10 门课程、300 份文件、合计至少 10,000 页/等价内容，含中英文、扫描公式、图表、Office、代码和 Notebook。此处是复现规模的方法提案，不新增响应时延 SLA。样本必须有跨课程、同义问法、相似标题、版本冲突和关键原文定位的人工 ground truth，重复拷贝一份文件不能验证检索质量。

报告硬件、系统、桌面版本、数据构成、模型、网络条件、解析/索引耗时、检索与活动耗时、资源峰值及可获得的用量信息。无图像能力、断网、取消导入、环境准备失败和恢复缺文件都应有异常证据。具体题集与评分细则由任务负责人提出，经教学人工评审校准。
