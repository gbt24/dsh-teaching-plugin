# 四类课程人工教学评审（AC19–AC22）执行说明

目的：用真实学生（用户本人）的真实解释与作答，检验教学是否帮助理解、是否如实记录掌握、是否支持独立迁移。自动生成的学生回答只能测试数据流，**不能替代本评审**。

## 准备

- 插件已安装到真实 Desktop profile，左侧栏有「AI 教学」入口。
- 每类课程准备 1 份真实资料（也可用 `samples/review/` 的样例）：AI（过拟合）、SICP（递归与迭代过程）、数学（导数与连续性）、考研（阅读理解与概念辨析，非编程非纯计算的样本）。
- 预期每类 10–20 分钟；可分批完成，进度与记录自动保存。

## 每类课程的操作

1. 打开「AI 教学」→ 建课程（填写目标与基础）→ 导入该类资料 → 确认课程草案 → 新建学习会话。
2. 先让 AI 讲解一个概念；然后按教学流程完成：学生尝试 → AI 诊断 → 针对性练习 → 迁移题。
3. 期间请至少做一次「用自己的话解释」和一次「新情境判断/迁移题」的**独立作答**（不看答案、不用提示）；需要时可以要求提示或完整答案，但请如实说明。
4. 完成后把以下内容导出/截图给验收者：目标、活动、AI 讲解要点、你的原回答、AI 反馈、你的自评（哪里有帮助/哪里没懂）。

## 评审要检查什么（人工）

- 目标适配：讲解是否服务于你的目标与基础。
- 来源准确：关键定义/结论是否来自资料、是否能定位原文，模型补充/外部来源是否区分。
- 直觉与正式知识连接：是否有直觉→准确表述→适用条件→类比边界的链。
- 学生参与：是否有你的尝试、诊断是否针对你的错误。
- 独立迁移：面对未见问题，你是否能选择概念并解释理由。
- 如实记录：若未掌握，系统应记录为未掌握并调整教学，而不是标成掌握。

## 四类课程的具体场景（对应 AC19–AC22）

| AC | 场景 | 需要的证据 |
| --- | --- | --- |
| AC19 | AI：过拟合与泛化；调整数据量/模型复杂度观察训练/验证差异；解释结果；新数据情境提出应对 | 资料引用、活动操作与真实输出、学生解释、迁移题作答 |
| AC20 | SICP：递归与过程；运行/修改/解释程序；独立分析未见程序 | Scheme 真实运行输出、学生预测与核对、独立分析记录 |
| AC21 | 数学：导数、连续与适用条件；图形与定义连接；反例；新函数判断 | 图形/公式、反例辨析、证明与数值分开、迁移作答 |
| AC22 | 考研：阅读/概念辨析（非编程、非纯计算）；干扰项诊断；未见材料变式 | 原文引用、误判依据诊断、逐层提示记录、变式作答 |

## 记录归档

评审结束后由验收者把每类课程的会话导出（插件「导出」功能或 `portability.export`）与本说明一起归档到 `docs/evidence/T08.md` 的 AC19–AC22 小节，并注明日期、资料来源、学生基础与自评。
