# 需求规格 v1.0

状态：用户已确认。日期：2026-11-04。依据：本次 Q1–Q40 逐轮访谈及最终汇总确认。

## 目标与成功含义

为学生提供基于本地知识库的通用课程教学。教学既要形成直觉，也要连接准确表述、适用条件和实际应用。学习结果以学生解释、辨析及独立迁移表现为证据；生成讲解、完成实验和掌握概念分别记录。

支持任意课程是课程范围要求；运行环境、资料格式、资源规模与验收样例分别按下表界定。四类验收课程不构成学科白名单。学科适配覆盖解释、计算、证明、程序、阅读与开放式论证等不同任务形态。

## 用户旅程

1. 学生安装插件，选择本地资料和当前课程，说明学习目标与基础。
2. 导入显示进度与问题清单；系统学习使用确认后的课程结构，随问随学可先使用已可读内容。
3. AI 在需要时诊断前置知识，给出与来源关联的解释及教学活动。
4. 学生操作图形、修改程序或回答问题；AI 根据新证据解释结果、提示、诊断并调整教学。
5. 学生可以跳过、追问、要求答案或切换讲解方式；学习证据如实记录。
6. 下次进入继续进度，按需复习；源资料变化时核对受影响内容。
7. 学生管理记录、导出成果或备份迁移。

## v1 不包含

多人账号/教师管理平台、在线数据同步、音视频资料处理、远端计算资源管理、插件外定时提醒、完整 IDE、所有原生实验环境随 HTML 一并打包、长期大规模学习效果对照研究。后续增加这些能力走需求变更。

## 完成与变更规则

- 阶段交付可以只覆盖部分 R，最终 v1 需要全部 R 对应验收有证据；阶段计划不会把后期需求变成可选项。
- “能生成页面”“能运行代码”“能独立迁移”分别验证。模型自评或模型代答不能代替真实学生教学评审。
- 当前无量化工期、费用、时延 SLA 或普遍学习增益承诺；测量与报告是实现责任，新增硬指标单列变更。
- 桌面版本、解析工具、检索技术、运行器、学习评分细则是实现待验证事项；它们不构成对用户需求的自动缩减。
- 原访谈外的架构细节在其他文件标为提案，由实现验证后冻结；改变课程范围、数据去向或交付能力需回到产品决策。
