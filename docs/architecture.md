# 架构提案

状态：计划提案，须经 T00 实际接口验证后冻结。产品要求以 [requirements.md](requirements.md) 为准；官方事实以 [桌面集成调研](research/harness-desktop-integration.md) 为依据。

## 总体形态

采用可安装的 Harness bundle，贡献 Host 侧教学能力与 Client 侧学习工作区。首期优先一个发布包及清晰内部 modules，按真实分发或复用需要再拆包。复用 Harness 的模型、工具和桌面载体，通过官方 extension points 集成。

```text
学生操作 ── 对话 + 持续教学区域
                  │
          HarnessBridge adapter
                  │
            Teaching module
          /        │        \
     Corpus     Learning    Activities
       │           │           │
   Sources      Evidence    Experiments
       \           │          /
              LocalState
                  │
             Portability
```

图示为内部职责关系，非官方包名或 SDK 签名。完整接口包含行为、不变量、错误与性能特点，见 [contracts.md](contracts.md)。多种文档解析器、实验语言与宿主内/独立页面渲染是明确需要不同 adapters 的 seams。

## Modules 与职责

| Module | 小 interface 的职责 | 内部隐藏的复杂度 |
| --- | --- | --- |
| HarnessBridge | 激活、连接宿主能力、发送教学命令/状态、卸载 | Desktop profile、版本兼容、Host/Client 通信、Slots、模型/工具 adapter、事件映射 |
| Corpus | 导入/刷新资料、查询证据、定位来源、提出/确认课程修订 | 格式解析、OCR/公式/图表、切分、检索、版本关系、不确定性、更新失效 |
| Teaching | 处理学习目标与输入、推进/插入/恢复教学、输出活动建议 | 学情诊断、先修关系、不同学科教学策略、来源优先与冲突、复习、模型编排 |
| Activities | 创建/更新/恢复可编辑教学活动 | 结构化图形/推导/动画/代码活动、活动版本、参数状态、持续视图、学生修改 |
| Experiments | 检查环境、准备、执行、取消并返回证据 | 多语言/方言 adapter、独立依赖、环境发现配置、进程与资源控制、验证、降规模 |
| Learning | 提交尝试/评价、查询学情、记录争议与复习建议 | 提示与答案暴露、独立性、评分依据、掌握状态、错题关联、重检与遗忘 |
| LocalState | 本地事务、修订、记录查询/清除、恢复 | 存储选型、迁移、冲突检测、失败恢复、数据删除与索引同步 |
| Portability | 导出成果、备份/恢复和迁移 | 可离线活动渲染、附件、运行说明、格式版本、路径重映射、校验与恢复 |

Interface tests 从调用方使用的同一 seam 验证行为。避免让 Teaching 了解各格式 parser 细节，或让每个 UI 操作自行维护掌握状态。跨 module 共享 contract，不互相导入私有 implementation。

## Host 与 Client

- Host 持有权威课程、学习证据、活动版本与实验执行状态；Client 维护可恢复视图和用户交互。
- 教学区域保存活动 ID 与修订状态，聊天消息引用该活动；追问、刷新和重启后能恢复同一活动。
- 模型输出先转为可校验的教学结果与活动描述，再交由执行/渲染 adapters；模型文本不直接充当任意 Host 执行指令。
- 单个学习会话绑定当前课程和学习目标；跨课程引用显式携带课程和来源。
- 复用宿主当前模型配置。识别扫描图像等能力需能力检查；模型不支持时通过明确的解析 adapter 完成或返回待处理状态，不隐式更换模型供应商。
- 卸载要清理监听、注册、视图与运行任务；持久学习数据按本地记录策略保留，可由学生显式删除。

## 本地数据与来源

候选为本地事务存储＋全文检索，是否增加本地语义检索由中英文、公式、同义表达检索基准决定。最终引擎、中文分词和 OCR 工具在 T00/T02 验证，不把模型提供商的 embedding 能力视为前提。

原资料采用读取与定位；学生资料原文件不被解析器改写。解析产物、索引、课程修订、学习记录和导出分别存储。资料内容可以按需用于云端模型请求；原始资料、网页和程序运行输出是待解释的数据，不自动成为执行授权。

来源最小结构：资料身份、不可混淆的修订、原文定位、内容类型、抽取状态。定位分别支持 PDF 原页面/区域、Office 段落/幻灯片、文本行/片段、Notebook 单元、代码行。没有可用置信度时记录“未知”，不伪造可靠度。关键公式/图表不确定性保留到讲解层。

更新产生新修订，列出受影响课程节点、引用和活动。结构/结论变更形成待确认草案；历史尝试仍指向旧版本，新解释可补充修正。掌握记录可以标记需复核，同时保留先前证据。

## 教学与评价

教学结果至少带有学习目标、讲解内容、证据引用/补充标识、直觉与正式表述的联系、适用条件、下一活动或练习建议。具体呈现按学科调整，不要求所有概念套同一段落模板。

学习状态分开表示：接触/讲解进度、练习状态、掌握评价、学生自述。一次尝试记录学生原答、当时已展示的提示/答案、活动与资料版本、验证方法和评价依据。跳过活动或模型代答不会生成独立完成证据。

客观核验使用实际计算/运行/测试结果。证明、解释、阅读和开放式回答使用可检查 rubric，明确依据与不确定性。掌握判定由多类证据支持；自动评分细则须通过四类课程教学评审，不能只依赖模型自信分数。

## 实验与生成内容

Python/JavaScript/Scheme adapters 先打通完整执行流程。Scheme 必须核对教材方言、运行器和所需教学库，区分语言不兼容与学生程序错误。

新增环境流程：识别教学需求和已有能力 → 提出可解释配置方案 → 独立环境内自动准备 → 冒烟运行 → 保存环境描述与版本 → 执行 → 返回证据。系统级改动进入学生选择分支；配置失败可撤销本次未完成状态。自动环境配置按接口支持新增语言，不等于承诺任意平台和资源必定安装成功。

依赖隔离与运行隔离分别处理：语言虚拟环境解决依赖冲突；执行还需核实宿主提供的文件、网络、进程、超时及取消控制。先复用已验证的 Harness 能力；缺失能力记录 gap 与 adapter 方案。默认任务采用教学所需的资源规模，重型任务用保持原理的小实验替代。

Client 动态活动在受限的渲染载体内运行，Host 交互通过明确消息契约。参数和代码修订可追踪，代码运行由 Experiments 执行。不能把任意教学 HTML 与 Host 访问混成一个权限面。

## 可独立导出与恢复

活动描述与状态为持久内容，宿主 Slots 是一种 renderer，离线 HTML 是另一种 renderer。离线包包含所需文字、公式、浏览器图形逻辑和资源；用离开 Harness 且断网的浏览器验证。Python/Scheme 等实验导出源码、环境说明、输入和验证结果，不假装可在纯 HTML 中自动运行。

备份携带格式版本、清单与校验数据，描述包含哪些本地源文件/衍生数据、哪些仅为外部来源引用。恢复时处理资料路径变化和缺失文件，保留可验证的历史证据；凭据继续由宿主管理。具体备份包含项与界面说明在 T07 实现验证，避免恢复后静默丢失引用。

## 故障与进展

所有长任务有可见阶段、取消和部分完成结果。已就绪课程可以在其他资料处理时继续使用。错误区分解析不确定、资料缺失、网络/模型能力不足、配置失败、执行失败和评价不确定；UI 提供下一步，掌握状态不因失败任务而推进。

质量优先通过来源和验证证据体现。记录模型调用、耗时与可获得的用量数据；费用未知就显示未知，不虚构费用，也不把需求解释为可以无限重试。
