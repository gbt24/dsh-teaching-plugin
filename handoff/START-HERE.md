# 实现交接入口

这是供用户自行转交实现 agent 的任务入口。需求已经用户确认；本聊天负责产品与计划，用户指定的实现 agent 负责被分配任务的实际代码和验证。

## 执行顺序

1. 阅读 [需求规格](../docs/requirements.md)，确认 R01–R40 及 v1 范围。完成条件：知道任务引用的 R 与整体范围的关系。
2. 阅读 [任务卡](task-cards.md) 中分配给你的任务及 [计划](../docs/plan.md) 中的前置条件。完成条件：前置证据已存在，写入所有权明确；缺条件时记录具体 gap，不用 mock 宣称通过。
3. 阅读 [协作契约](../docs/contracts.md)。新建或修改 interface 时同时读取 [架构提案](../docs/architecture.md)。完成条件：共享对象、错误、修订与学习状态语义明确。
4. 涉及 Harness 时读取 [官方核对](../docs/research/harness-desktop-integration.md) 与 [技术登记](../docs/technical-decisions.md)，以锁定版本源码/声明确认用法。完成条件：实际版本与依赖归属有证据；不把可变 master 文档当实际兼容结果。
5. 实现一个可验收任务，运行与改动相关的测试及 [验收 case](../docs/acceptance.md)。完成条件：任务退出条件有实证，故障/取消/恢复按实际影响验证。
6. 写 `docs/evidence/Txx.md` 并回报协调者。完成条件：报告清楚区分代码完成、自动验证、真实桌面操作和教学人工评审，列出未通过项及下一任务入口。

## 建议用户首先派发的任务

**T00**。先只读采集本机 Desktop、版本、bundled CLI 和可用 runtime 指纹；安装路径不明时自行从环境查找。向协调者立即回报 preflight。

用户将 T00 分配给实现 agent 后，该 agent 在任务范围内完成最小真实 spike；改变系统级环境或产品范围按已确认规则处理。本计划本身不触发 agent 派发或执行。环境不存在时记录缺失事实与继续条件，不能用普通 Web 或 mock 替代桌面验收。

## Evidence 模板

```text
任务 / 状态 / 日期
实际基线：OS、架构、Desktop、runtime、插件、关键依赖/commit
改动文件与公共 interface 变化
覆盖：Rxx、ACxx
实际执行：命令/操作、结果、可复查日志/截图位置
验证级别：自动测试 / 真实 Desktop / 人工教学（各自状态）
失败、局限、外部缺失与保留数据
下一步：任务入口、已冻结事实、仍需验证事项
```

学习者原资料与凭据不直接粘贴进报告；报告可以使用来源身份和经过处理的最小片段证明定位与行为。
